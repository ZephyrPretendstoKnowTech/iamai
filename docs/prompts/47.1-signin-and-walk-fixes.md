# 47.1 — Sign-in regression, and walk fixes on 47's surfaces

Precondition: 47 committed and green (37a1c61). This is a hotfix; do it before 48.

## Part 1 — Nobody can sign in on the live site

Found on getiamai.com at 37a1c61: `Sign in with Microsoft` redirects to Microsoft, the
silent sign-in succeeds, the browser returns to `/rollout/` — and the page renders
signed out at `#/connect`. Every attempt.

Cause. MSAL returns the auth response in the fragment (`#code=…&client_info=…&state=…`).
`useHashRoute` in `src/ui/shell/AppShell.tsx` runs `resolveHash` in its `useState`
initialiser, synchronously on first render; an unrecognised hash resolves to
`{ route: 'connect', redirect: '#/connect' }` and `window.history.replaceState` wipes
the fragment before `initAuth()` (an effect) calls `handleRedirectPromise()`, which
reads the fragment. The smoke test never sees this because the mock sign-in does not go
through MSAL.

1. `resolveHash`: a hash that is an auth response — begins with `code=`, `error=`,
   `access_token=` or `id_token=`, or contains `state=` and `client_info=` — resolves to
   `{ route: 'home', redirect: null }`. It is never rewritten. The `home` effect in
   `App.tsx` already waits for `ready`, so after `handleRedirectPromise` settles the
   page lands on Plan (or Connect) as today.
2. Unit tests on `resolveHash` for the four response shapes, and for `#/connect`,
   `#/start`, `#`, `#/roadmap/step/x` staying as they are.
3. Smoke: load `/rollout/#code=abc&client_info=def&state=ghi` on the mock and assert
   the fragment is intact when the first frame renders (before auth init resolves).
4. `docs/qa/review-method.md` gains one line: any change to routing is walked on the
   live site with a real sign-out and sign-in, because the mock cannot cover MSAL.
