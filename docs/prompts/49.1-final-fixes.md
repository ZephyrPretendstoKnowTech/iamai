# 49.1 — The final pass findings, and the depth pass

Precondition: 49 committed and green (4b60855). Read `docs/design/target-state.md` and
`docs/qa/page-contracts.json` in full — both were updated by the reviewer in the same
commit as this prompt (a two-depth surface rule; `forbidEverywhere` strings). Neither is
yours to edit. This is the closing fix prompt: after it, only the demo rebuild remains.

## Part 1 — No artifact ever contains a placeholder

1. The JSON tab, Download JSON and PowerShell for "Stop attackers adding their own MFA
   method" render `__IAMAI_SETUP_QUESTION_2_EXCLUSIONGROUPS__` when the exclusions
   group does not exist. Placeholder resolution: when the referenced object exists,
   its id; when it does not, the JSON omits that clause and a single caption above the
   tabs says "The exclusions group doesn't exist yet — this JSON omits it; re-download
   after that step." Rename the placeholder tokens (`SETUP_QUESTION` is dead
   vocabulary). Test: no rendered surface, no downloaded artifact (JSON, PowerShell,
   ICS, CSV, plan file, prompts, bundle, print) contains any `forbidEverywhere` string;
   the smoke generates each artifact and asserts it.
2. The inventory walk opens every tab in a `.tabs` group before capture, so
   non-default tabs are inside the forbid and budget checks. This is how item 1
   escaped rule 12.

## Part 2 — Print is the product on paper

3. The print layout still renders the old step body — `Kind: New policy`, `Proposed
   name:`, `What the last 30 days say`, `Handle with care`, pre-48 populations, the
   what-could-go-wrong entries concatenated with colons. Rebuild it from the same
   content functions the Step surface uses: page 1 the posture summary, then the waves
   as the Plan renders them, then each step's first-open content followed by its More
   content, new populations and evidence lines included. Then delete the dead chain
   that only the old print kept alive (`src/roadmap/next.ts`, `src/copy/next.ts`, and
   whatever else has no consumer after this — verify with the import graph).
4. The print DOM currently mounts on every screen: `.print-only` computes
   `display: block`, and "IAMAI plan for … · prepared …" leads every page's extracted
   text. Print content exists only under `@media print`, mounted on demand when the
   Export button or `window.print` fires, and never in the screen DOM otherwise. This
   is also the screenshot-freeze cause.

## Part 3 — Content fixes

5. Manager notes are keyed to the wrong goal: the registration step carries the
   MFA-for-all note ("2 people will confirm sign-ins with the Authenticator app…").
   Key them per goal; test: every manager note names its own control's effect, never
   another's.
6. The emergency-access create action gains the clause 49 Part 1 specified: "…assign
   Global Administrator permanently, then register a passkey or FIDO2 key and record
   where its credential is kept."
7. Portal steps say "Register security information", never `urn:user:…`. The URN may
   appear in the JSON only.
8. The Recovery card's "Setup has no answer for where these credentials are kept"
   becomes "Not recorded. Write it here by hand before filing this card." — the last
   user-facing "Setup" in the product (the global forbid now enforces it).
9. The answered question chip keeps reading `none seen · answer` after Save. The chip
   reflects its state: `mail-sending devices 1 listed · change`. Test on the mock:
   answer, assert the label, clear, assert it reverts.

## Part 4 — Mechanics

10. `Skip this step` does nothing (no dialog, no state change, no undo). Make it real:
    click → one inline confirm line ("Skip this step? It stays in the plan as Skipped.
    Skip · Cancel") → the row shows `Skipped`, the step shows `Unskip`, the header
    counts exclude it, the plan file stores it. On a Blocked step it works the same —
    skipping a blocked step is exactly when someone wants it.
11. Plan settings idempotence: the start-date input shows the plan's effective start;
    entering the value shown changes nothing (setting it moved Sep 20 to Sep 19 on the
    live tenant and produced a wave window opening on a Sunday). Wave windows and
    foundation dates clamp to working days. Add `Reset to default` in the settings
    popover, which clears the stored override (the reviewer's walk left one behind on
    the test tenant).

## Part 5 — The depth pass

The owner's read after using it: the flattening went one step too far — sections and
steps don't differentiate, and some text is hard to read. The fix is hierarchy inside
the token system, not the old dashboard back.

12. Two surface depths (target-state §8.6, updated): each wave, and each export entry,
    is a raised panel — `--bg-raised`, hairline border, 8px radius — with its header
    inside and its rows separated by hairlines within it. The open step keeps its
    raised treatment inside the wave panel. Nothing else gains a box; per-step tiles do
    not return. Update the design lint: radius ≤8px allowed on `.wave` and
    `.export-card` panels only; `--bg-raised` allowed on them.
13. Row hierarchy: the title at weight 500; status, who and date in `--ink-3`; a hover
    surface on rows; the status column fixed-width so the dots align down the page.
    Wave headers gain a size step (`--t-4` → keep serif) and clear space above.
14. Readability: `--ink-3` darkens to #6B6B65 (light) and lightens to #8A887F (dark);
    nothing user-facing renders below 13px — the 12px uses move to 13; portal steps
    and policy names render mono at 13px; step-body line-height 1.55. The layout audit's
    floor rises to 4.5:1 for all text below 18px, both modes, and the build fails
    under it. Report the new minima.
